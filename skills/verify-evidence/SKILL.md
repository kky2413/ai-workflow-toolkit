# 증거가 있는 검증

## 사용할 때
기능 구현이 끝났다고 생각하거나 변경 파일·보고서를 최종 확인할 때.

## 절차
1. 필수 요구마다 실제 결과 파일·구현 위치·검증 방법을 연결합니다.
2. '테스트가 존재한다'와 '테스트를 실행해 통과했다'를 구분합니다.
3. 정상 입력·빈 입력·중복·누락·경계 조건·오류 복구 가운데 관련 있는 사례를 선택합니다.
4. 실제 실행 명령, 종료 코드, 기대 출력과 관찰 출력을 기록합니다.
5. 검증 결과가 비어 있으면 성공이라고 표시하지 않습니다.
6. 출력 파일을 다시 읽고 행·열·수치·형식 등을 원자료로 교차 확인합니다.
7. 실패 항목, 실행하지 못한 테스트, 남은 위험을 숨기지 않습니다.

## 결과
- 요구사항별 검증 표
- 실제 실행 명령·관찰값
- 미완성·미검증 항목
- 변경 사항과 결과물 경로

## 금지
실행하지 않은 테스트의 성공 주장, 승인 우회, 원본 자료 외부 전송.
