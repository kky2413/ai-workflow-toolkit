# 데이터 계산 전후에 확인할 것

## 행 하나가 무엇을 의미하나요?
제품 한 개, 로트 한 개, 검사 이력 한 건은 서로 다릅니다. 데이터를 합치거나 집계하기 전에 한 행의 의미와 중복 여부를 확인해야 합니다.

## 식별자는 숫자가 아닐 수 있습니다
ID 00125와 125는 같은 값이라고 보장할 수 없습니다. 공백이나 대소문자도 임의로 수정하지 않습니다.

## 연결 전에 예상 행 수를 확인합니다
예를 들어 왼쪽 표의 A 로트 생산수량은 100, 오른쪽 표의 A 로트 기록이 2개라면 결합 이후 100이 두 번 나타날 수 있습니다. 이를 다시 합산하면 200이 됩니다. join_audit.py로 키의 중복·미매칭·예상 행 수를 확인하세요.

## 비율의 분모가 중요합니다
A: 99개 통과 / 100개 검사, B: 1개 통과 / 2개 검사.

각 행 합격률의 단순 평균은 74.5%입니다. **전체 검사 개수 기준 합격률**이 목적이라면 (99+1)/(100+2)×100 = 약 98.04%입니다. 두 방식 중 어떤 계산이 맞는지는 요구된 집계 정의로 판단합니다.

## 합격 규격은 임의로 만들지 않습니다
기준 100 이하와 100 미만은 다릅니다. 사용자나 근거 문서에서 명시된 기준·상하한·경계 포함 여부를 확인한 뒤 rule_check.py에 입력하세요.

## 빈 값과 0은 다릅니다
측정되지 않은 값, 숫자 0, 결측 표기 'N/A'는 같지 않을 수 있습니다. 자동 대체하기 전에 업무 의미를 확인합니다.

## 최종 검산
- 원본 행 수·고유 키·결합 전후 행 수
- 같은 기간·제품·설비·단위의 자료인지
- 분자·분모의 모집단이 맞는지
- 숫자가 아닌 입력·분모 0·중복 키·빈 데이터의 실패 처리
- 소표본을 손으로 직접 계산한 기대값
- 출력 파일을 다시 열어 주요 값과 계산식 대조

**데이터 처리 코드가 테스트에 통과했다고 실제 계산의 업무적 의미까지 검증된 것은 아닙니다.**
