# Codex 명령어 안내

## 1. 일반 터미널과 Codex 입력창 구분

일반 터미널에서 `codex`를 실행하면 Codex 대화형 입력창이 열립니다. 슬래시 명령어는 **Codex 안에서** 입력하는 명령어입니다.

| Codex 입력창 | 기능 |
| --- | --- |
| `/status` | 현재 모델·작업 디렉터리·권한·세션 상태 확인 |
| `/model` | 제공되는 모델과 추론 수준 선택 |
| `/plan` | 구현 전 계획 모드로 전환(지원 시) |
| `/diff` | Git 변경 사항 확인 |
| `/review` | 현재 작업 내용의 코드 검토 요청 |
| `/compact` | 긴 대화의 맥락을 요약해 컨텍스트 관리 |
| `/mcp` | 연결된 MCP 서버·도구 확인 |
| `/skills` | 사용 가능한 Skill 확인(지원 시) |
| `/new` | 새로운 대화 시작 |
| `/resume` | 저장된 이전 대화 재개(지원 시) |
| `/exit` 또는 `/quit` | Codex를 종료하고 셸로 복귀 |

버전·설정에 따라 지원 명령어와 메뉴가 다릅니다. Codex 입력창에서 `/`를 눌러 **현재 환경에 표시된 목록**을 우선 확인하세요.

## 2. 일반 터미널 명령어

| 명령어 | 역할 |
| --- | --- |
| `pwd` | 현재 폴더 확인 |
| `ls -la` | 숨김 파일을 포함한 목록 확인(Linux) |
| `cat README.md` | 터미널에서 README 내용 읽기 |
| `cd 폴더명` | 폴더 이동 |
| `git clone 주소` | 저장소 복제 |
| `git status` | Git 변경 상태 확인 |
| `git diff` | 수정된 코드 차이 확인 |
| `python3 파일.py` | Python 프로그램 실행 |
| `python3 -m unittest discover -s tests -v` | 자동 테스트 실행 |

Windows PowerShell에서는 `python`을 사용할 수 있으며, 파일·폴더 삭제 명령어 등은 Linux Bash와 다릅니다.

## 3. 효과적인 실행 순서

1. 터미널에서 `pwd`와 `ls`로 폴더 확인
2. README와 관련 파일 확인
3. 필요하면 `codex` 실행
4. Codex의 `/status`, `/model` 확인
5. 요구사항·변경 범위·검증 방법을 명확하게 요청
6. 수정 결과에 `/diff`·`/review` 적용(지원 시)
7. 테스트 실행 결과와 실제 파일 확인
8. `/exit`으로 셸에 복귀

## 4. 주의할 점

- `/compact`는 누적 사용량을 지우는 기능이 아닙니다. 긴 대화의 맥락을 정리할 때 선택적으로 사용합니다.
- `/review`는 코드 검토 보조 기능입니다. 실행 테스트나 수동 검증을 대체하지 않습니다.
- 슬래시 명령어가 보이지 않는 경우 현재 설치된 버전의 지원 범위부터 확인하세요.
- 권한이나 외부 연결 설정은 현재 작업 환경의 정책을 우선합니다.
