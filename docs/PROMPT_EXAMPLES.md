# Codex 프롬프트 예시 — 분석 → 구현 → 이해도 점검

이 문서는 **현재 작업 폴더의 실제 자료를 바탕으로** Codex에 작업을 요청할 때 활용하는 한국어 프롬프트 예시입니다. 특정 프로젝트의 정답이나 완성 결과물이 아닙니다.

**사용 순서:** ① 작업 시작 전에 분석 프롬프트 → ② 분석 계획을 확인한 뒤 구현 프롬프트 → ③ 진행 과정이나 완료 직전에 이해도 확인 프롬프트 → ④ 스스로 다섯 가지 질문에 답해 보기.

각 프롬프트는 **Codex의 대화 입력창에 넣는 일반 문장**이며 터미널 명령어가 아닙니다. 실제 환경에서 허용된 AI 사용 범위 내에서만 사용하세요. 참고 저장소를 아직 Clone하지 않았다면 경로 안내 문장을 생략해도 됩니다.

---

## 예시 1. 작업 시작 전: README와 자료 분석

**언제 사용하나요?** 낯선 작업 폴더에 처음 들어갔고, 아직 실제 구현을 시작하지 않았을 때 사용합니다.

~~~text
현재 작업 폴더의 실제 과제 README와 제공된 파일을 먼저 분석해 주세요.

1. 과제의 최종 목표를 쉬운 한국어로 설명해 주세요.
2. 반드시 만들어야 하는 파일과 저장 경로를 정리해 주세요.
3. 입력 데이터의 종류, 주요 열, 기존 코드 구조를 파악해 주세요.
4. 필수 요구사항과 선택사항을 구분해 주세요.
5. 완료 여부를 판단할 테스트와 검증 방법을 정리해 주세요.
6. 요구사항에서 불명확한 부분과 확인이 필요한 업무 기준을 알려주세요.
7. 제한 시간 안에 필수 기능부터 완성할 수 있도록 우선순위별 계획을 세워 주세요.

필요하다면 ~/ai-workflow-reference/docs/TOOL_CATALOG.md 및
~/ai-workflow-reference/docs/WORKFLOWS.md를 확인해
이번 작업과 관련 있는 도구만 선택해 주세요.
참고 자료에 접근이 제한되면 우회하지 말고 알려주세요.

아직 코드는 수정하지 말고 먼저 분석 결과와 실행 계획을 보여 주세요.
프로젝트의 실제 요구사항을 최우선으로 적용하고,
외부 자료 전송이나 허용되지 않은 도구 사용은 하지 마세요.
~~~

**본인이 확인할 내용:** Codex가 실제 README를 읽었는지, 제출·결과 파일의 경로가 맞는지, 필수 기능과 선택 기능을 구분했는지 확인합니다. 잘못 이해한 부분은 구현 전에 바로잡습니다.

## 예시 2. 계획 확인 후: 필수 기능부터 구현

**언제 사용하나요?** 예시 1의 분석 결과를 직접 읽고, 목표와 주요 구현 순서를 확인했을 때 사용합니다.

~~~text
방금 정리한 계획을 기준으로 가장 중요한 필수 기능부터 구현해 주세요.

기존 프로젝트 구조와 원본 데이터는 보존해 주세요.
참고 저장소의 코드는 실제로 필요한 경우에만 활용하고,
과제 결과물을 기존 코드 전체로 대체하지 마세요.

먼저 최소한의 정상 실행 결과를 만들고,
실제 명령으로 동작을 검증해 주세요.
이후 나머지 필수 요구사항을 우선순위대로 구현해 주세요.

각 작업 단계가 끝날 때마다 다음 네 가지를 짧게 알려 주세요.

- 무엇을 구현하거나 변경했는지
- 왜 그 방법을 선택했는지
- 무엇을 실행해 검증했고 결과가 어땠는지
- 아직 구현하지 못했거나 확인하지 못한 것은 무엇인지

테스트를 실행하지 않았다면 통과했다고 말하지 말고,
데이터나 기준값이 부족하면 임의로 채우지 마세요.
~~~

**본인이 확인할 내용:** 구현한 코드가 실제 요구사항을 충족하는지, 검증 명령어를 실제로 실행했는지, 파일과 출력 결과가 존재하는지 직접 확인합니다. Codex의 설명만으로 검증을 완료했다고 판단하지 않습니다.

## 예시 3. 진행 중·완료 전: 내가 한 일을 이해하기

**언제 사용하나요?** 주요 구현 단계 직후 또는 완료 전, 실제 코드와 작업 기록을 본인이 이해하는지 점검할 때 사용합니다.

~~~text
지금까지 실제 구현한 기능을 기준으로 제가 반드시 이해해야 할 내용을 정리해 주세요.

구현 목적, 핵심 처리 흐름, 선택한 방법과 대안,
실제 검증 명령과 결과, 수정한 오류, 남은 한계를 구분해 주세요.
확인되지 않은 내용은 만들어내지 마세요.
~~~

**이해도 연습을 더 하고 싶다면** 다음 문장을 별도로 보낼 수 있습니다.

~~~text
앞서 정리한 실제 구현 내용에 대해 제가 스스로 설명할 수 있는지
확인하는 질문을 다섯 개 제시해 주세요.
정답을 미리 작성하지 말고 한 번에 질문 하나씩 물어봐 주세요.
제가 답하면 현재 코드와 실제 테스트 기록을 기준으로
사실과 다른 부분만 지적해 주세요.
~~~

**본인이 확인할 내용:** 코드가 어떤 입력을 받고 어떤 출력을 만드는지, 수치를 어떻게 계산하는지, 어떤 오류를 수정했는지, 실제로 한 검증과 하지 못한 검증을 구별할 수 있는지 확인합니다.

## 예시 4. 스스로 확인할 다섯 가지 질문

아래 항목은 **AI에 실행을 시키는 명령이 아니라 자신의 작업을 설명하기 위한 점검 기준**입니다.

| 구분 | 스스로 답할 질문 |
| --- | --- |
| **무엇을** | 과제의 목적과 내가 실제 완성한 기능은 무엇인가요? |
| **왜** | 선택한 기술·계산식·구현 방식의 이유는 무엇인가요? |
| **어떻게** | 자료를 읽고 처리한 구체적인 순서는 어떻게 되나요? |
| **검증** | 실제로 실행한 테스트와 관찰한 결과는 무엇인가요? |
| **한계** | 수정한 오류와 끝까지 확인하지 못한 부분은 무엇인가요? |

**기억하기:** 무엇을 → 왜 → 어떻게 → 검증 → 한계.

마지막 설명은 작업자가 직접 이해하고 실제 자료와 맞춰 작성해야 합니다. AI 사용이 허용되지 않는 후속 단계에서는 Codex를 사용하거나 AI가 작성한 답변을 대신 제출하지 마세요.

## 파일 경로·사용 범위 주의

- 위 `~/ai-workflow-reference`는 예시 Clone 위치입니다. 실제 경로가 다르면 수정하세요.
- 참조 저장소 안의 `AGENTS.md`가 다른 작업 폴더에 자동 적용된다고 가정하지 마세요.
- 현재 작업의 README와 운영 규칙을 우선하세요. 허용되지 않은 외부 전송·개인 AI 계정 연결·승인 우회·설정 변경은 하지 않습니다.
- 예시 프롬프트는 **과제별 파일명·기준값·정답을 미리 알고 있다는 가정이 없습니다.**
- 구현된 코드, 실제 실행 결과, 본인이 확인한 내용에 근거하여 설명하세요.
