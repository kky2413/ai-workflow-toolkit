# Codex 작업 요청문 모음

**단계별로 긴 프롬프트를 활용하려면 [프롬프트 예시](PROMPT_EXAMPLES.md)를 참고하세요.** 분석 → 구현 → 이해도 점검 순서와 자기 설명 기준이 담겨 있습니다.

아래 문장을 현재 프로젝트에 맞게 수정해 사용합니다. 응답에서 확인되지 않은 사실은 추정이라고 구분하도록 요청합니다.

## 1. 프로젝트 이해
> 현재 작업 폴더의 README와 관련 소스 파일을 확인하고 목표·필수 기능·완료 기준·제약을 정리해 주세요. 먼저 필요한 파일 목록과 미확인 사항을 간결히 보고하고, 아직 코드는 수정하지 마세요.

## 2. 실행 계획
> 확인된 요구사항만 기준으로 가장 작은 구현 계획을 작성해 주세요. 각 단계에 수정할 파일, 검증 명령어, 완료 조건을 적고 불분명한 부분은 질문으로 분리해 주세요.

## 3. 기능 구현
> 우선순위가 가장 높은 미완료 요구사항만 구현해 주세요. 기존 동작을 유지하고 필요한 파일만 수정하며, 변경 이유와 실행 가능한 테스트 결과를 알려 주세요.

## 4. 오류 해결
> 실제 오류 메시지와 실행 명령을 먼저 확인하고 재현 가능한지 검사해 주세요. 원인을 좁혀 최소 수정 후 동일한 테스트를 다시 실행하고, 미해결 문제가 있으면 명시해 주세요.

## 5. 결과 검토
> 현재 코드와 산출물을 요구사항별로 대조해 주세요. 확인된 항목, 검증하지 못한 항목, 남은 문제를 구분하고 실제 실행한 명령과 관찰 결과만 보고해 주세요.

## 6. 작업 인수인계
> 현재까지의 결정·수정 파일·실행 테스트·남은 문제·다음 작업을 짧은 인수인계 메모로 정리해 주세요. 실행하지 않은 검사나 확인되지 않은 성과는 적지 마세요.

## 7. 외부 도구 없이 확인 가능한 대안
> 사용 가능한 로컬 도구부터 확인하고, 설치나 외부 접속이 필요한 경우 목적과 대안을 설명한 뒤 현재 작업 환경에서 허용되는 방법만 사용해 주세요.

## 8. 다중 파일 분석·품질 보고서
> 먼저 실제 자료의 컬럼명과 파일 간 연결 키를 확인해 주세요. 분자·분모의 의미와 단위, 품질 판정 기준이 없으면 임의로 결정하지 마세요. 확인된 계산식만 설정에 반영하여 표를 작성하고 원본 데이터로 역산 검증해 주세요.


## 9. 복잡한 데이터 파일 검증
> 실제 원본 파일을 먼저 확인하고, 각 행의 의미와 ID·단위·기간을 정리해 주세요. 파일을 합쳐야 한다면 중복 키·미매칭·연결 후 예상 행 수를 먼저 검사해 주세요. 계산의 분자·분모를 명시하고 원본 행과 독립적으로 검산해 주세요. 기준이 없으면 합격/불합격을 만들지 마세요.

## 10. 기존 웹 앱 수정
> 프로젝트 README의 실행 방법을 읽고 실패하는 실제 화면·API를 재현해 주세요. 기존 구조를 최대한 유지하여 해당 기능만 수정하고, 로컬 HTTP 상태·반환 내용·화면 오류를 확인해 주세요. 배포나 외부 전송은 하지 마세요.

## 11. 문서·보고서 작성
> 확인된 원본 자료와 요구된 결과 형식을 먼저 대조해 주세요. 표의 수치는 계산식·단위·기간·출처를 적고, 검증하지 못한 해석은 별도로 구분해 주세요. 출력 파일을 다시 열어 누락·잘림·표 오타를 확인해 주세요.

## 12. 새 대화로 인계
> 현재 실제 프로젝트 경로와 수정 파일, 실행한 테스트·관찰한 결과, 완료 기준, 남은 문제, 바로 다음 작업을 짧게 정리해 주세요. 파일 내용과 대조되지 않은 주장은 포함하지 마세요. 전역 설정이나 프로그램 설치는 반복하지 마세요.
